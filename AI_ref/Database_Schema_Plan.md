# RBPDB Database Schema Implementation Plan

This plan reflects the clarified [ERD](./ERD.md) and project specification. It is design documentation only; no SQLAlchemy models or migrations are included.

## Conventions

- Use PostgreSQL `INTEGER GENERATED BY DEFAULT AS IDENTITY` for integer primary keys.
- Use `TIMESTAMPTZ` for all timestamps. `created_at` and `updated_at` are non-null; `created_at` defaults to the current timestamp, and `updated_at` defaults to it and is refreshed on updates.
- Use a database update trigger or equivalent centralized persistence mechanism to refresh `updated_at` consistently.
- Use bounded `VARCHAR` columns as constrained in the specification. Persist enum-like values as strings with SQL `CHECK` constraints.
- A nullable field is marked explicitly below. All other listed fields are non-null.

## Tables

### `users`

Purpose: user identity and profile information; soft deletion state.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `user_id` | `INTEGER` identity | NOT NULL | Primary key |
| `username` | `VARCHAR(50)` | NOT NULL | Unique; length 3–50 |
| `email` | `VARCHAR(254)` | NOT NULL | Unique; valid email format enforced at application boundary |
| `display_name` | `VARCHAR(100)` | NOT NULL | Length 1–100 |
| `deleted_at` | `TIMESTAMPTZ` | NULL | Set when account is soft-deleted |
| `created_at` | `TIMESTAMPTZ` | NOT NULL | Default current timestamp |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL | Default current timestamp; refreshed on update |

Foreign keys: none. `user_id` is not a foreign key.

### `roles`

Purpose: reference table of assignable roles.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `role_id` | `INTEGER` identity | NOT NULL | Primary key |
| `role_name` | `VARCHAR(16)` | NOT NULL | Unique; CHECK: `student`, `faculty`, `admin` |

Foreign keys: none. Seed the three role values, including `student`.

### `user_roles`

Purpose: associates users with roles.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `user_role_id` | `INTEGER` identity | NOT NULL | Primary key |
| `user_id` | `INTEGER` | NOT NULL | FK → `users.user_id` |
| `role_id` | `INTEGER` | NOT NULL | FK → `roles.role_id` |

Unique: `(user_id, role_id)`.

### `threads`

Purpose: shared thread identity, creator, type, access level, and timestamps.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `thread_id` | `INTEGER` identity | NOT NULL | Primary key |
| `user_id` | `INTEGER` | NOT NULL | FK → `users.user_id`; thread creator |
| `thread_type` | `VARCHAR(16)` | NOT NULL | CHECK: `lab`, `course`, `project` |
| `restriction_level` | `VARCHAR(16)` | NOT NULL | CHECK: `open`, `restricted`, `closed` |
| `created_at` | `TIMESTAMPTZ` | NOT NULL | Default current timestamp |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL | Default current timestamp; refreshed on update |

Unique: none specified.

### `project`

Purpose: project-specific fields for a project thread.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `thread_id` | `INTEGER` | NOT NULL | Primary key and FK → `threads.thread_id`; referenced thread must have type `project` |
| `name` | `VARCHAR(200)` | NOT NULL | Length 1–200 |
| `description` | `VARCHAR(5000)` | NULL | Maximum length 5000 |

### `course`

Purpose: course-specific fields for a course thread.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `thread_id` | `INTEGER` | NOT NULL | Primary key and FK → `threads.thread_id`; referenced thread must have type `course` |
| `name` | `VARCHAR(200)` | NOT NULL | Length 1–200 |
| `description` | `VARCHAR(5000)` | NULL | Maximum length 5000 |

### `lab`

Purpose: lab-specific fields for a lab thread.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `thread_id` | `INTEGER` | NOT NULL | Primary key and FK → `threads.thread_id`; referenced thread must have type `lab` |
| `name` | `VARCHAR(200)` | NOT NULL | Length 1–200 |
| `description` | `VARCHAR(5000)` | NULL | Maximum length 5000 |

Each thread must have exactly one matching subtype and no mismatched subtype. Enforce this with deferred database constraint triggers, validating the final state at transaction end.

### `user_threads`

Purpose: associates users with project authorship, course attendance, or lab membership.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `user_thread_id` | `INTEGER` identity | NOT NULL | Primary key |
| `user_id` | `INTEGER` | NOT NULL | FK → `users.user_id` |
| `thread_id` | `INTEGER` | NOT NULL | FK → `threads.thread_id` |

Unique: `(user_id, thread_id)`.

### `posts`

Purpose: announcement or discussion content attached to a thread.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `post_id` | `INTEGER` identity | NOT NULL | Primary key |
| `post_type` | `VARCHAR(16)` | NOT NULL | CHECK: `announcement`, `discussion` |
| `user_id` | `INTEGER` | NOT NULL | FK → `users.user_id`; author |
| `thread_id` | `INTEGER` | NOT NULL | FK → `threads.thread_id` |
| `title` | `VARCHAR(200)` | NOT NULL | Length 1–200 |
| `content` | `VARCHAR(10000)` | NOT NULL | Length 1–10000 |
| `restriction_level` | `VARCHAR(16)` | NOT NULL | CHECK: `inherited`, `open`, `restricted`, `closed`; default `inherited` |
| `mod_status` | `VARCHAR(32)` | NOT NULL | CHECK: `active`, `reported`, `hidden_by_moderator`; default `active` |
| `created_at` | `TIMESTAMPTZ` | NOT NULL | Default current timestamp |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL | Default current timestamp; refreshed on update |

Unique: none specified.

### `comments`

Purpose: replies to a post or to another comment. Comment-level restrictions are included per the clarified soft-delete requirement; `inherited` preserves the usual parent-post behavior.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `comment_id` | `INTEGER` identity | NOT NULL | Primary key |
| `user_id` | `INTEGER` | NOT NULL | FK → `users.user_id`; author |
| `post_id` | `INTEGER` | NOT NULL | FK → `posts.post_id` |
| `p_comment_id` | `INTEGER` | NULL | Nullable parent-comment FK; when present, parent must be on the same post |
| `content` | `VARCHAR(5000)` | NOT NULL | Length 1–5000 |
| `restriction_level` | `VARCHAR(16)` | NOT NULL | CHECK: `inherited`, `open`, `restricted`, `closed`; default `inherited` |
| `mod_status` | `VARCHAR(32)` | NOT NULL | CHECK: `active`, `reported`, `hidden_by_moderator`; default `active` |
| `created_at` | `TIMESTAMPTZ` | NOT NULL | Default current timestamp |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL | Default current timestamp; refreshed on update |

Foreign keys: `user_id → users.user_id`; `post_id → posts.post_id`; composite `(p_comment_id, post_id) → comments(comment_id, post_id)`.

Unique: `(comment_id, post_id)` is required as the target key for the composite parent-comment FK. The primary key already guarantees `comment_id` uniqueness.

### `tags`

Purpose: reference table of unique categorization tags.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `tag_id` | `INTEGER` identity | NOT NULL | Primary key |
| `tag` | `VARCHAR(50)` | NOT NULL | Unique; length 1–50 |

### `threads_group`

Purpose: parent-child edges in the Lab→Course→Project hierarchy.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `thread_group_id` | `INTEGER` identity | NOT NULL | Primary key |
| `p_thread_id` | `INTEGER` | NOT NULL | FK → `threads.thread_id`; parent |
| `c_thread_id` | `INTEGER` | NOT NULL | FK → `threads.thread_id`; unique, enforcing at most one parent per child |

Unique: `(p_thread_id, c_thread_id)` as well as `c_thread_id`.

Checks/triggers: prohibit self-parenting. A database trigger enforces only Lab→Course and Course→Project relationships; a Project cannot have children.

### `threads_tag`

Purpose: many-to-many association between threads and tags.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `thread_tag_id` | `INTEGER` identity | NOT NULL | Primary key |
| `thread_id` | `INTEGER` | NOT NULL | FK → `threads.thread_id` |
| `tag_id` | `INTEGER` | NOT NULL | FK → `tags.tag_id` |

Unique: `(thread_id, tag_id)`.

### `post_tag`

Purpose: many-to-many association between posts and tags.

| Column | Type | Nullability | Constraints |
|---|---|---|---|
| `post_tag_id` | `INTEGER` identity | NOT NULL | Primary key |
| `post_id` | `INTEGER` | NOT NULL | FK → `posts.post_id` |
| `tag_id` | `INTEGER` | NOT NULL | FK → `tags.tag_id` |

Unique: `(post_id, tag_id)`.

## Relationships

| Type | Parent | Child | Required foreign keys |
|---|---|---|---|
| One-to-many | `users` | `threads` | `threads.user_id → users.user_id` |
| One-to-many | `users` | `posts` | `posts.user_id → users.user_id` |
| One-to-many | `users` | `comments` | `comments.user_id → users.user_id` |
| Many-to-many | `users` | `roles` | `user_roles.user_id → users.user_id`; `user_roles.role_id → roles.role_id` |
| One-to-one subtype, optional at base-row level | `threads` | `project` | `project.thread_id → threads.thread_id`; exact subtype trigger |
| One-to-one subtype, optional at base-row level | `threads` | `course` | `course.thread_id → threads.thread_id`; exact subtype trigger |
| One-to-one subtype, optional at base-row level | `threads` | `lab` | `lab.thread_id → threads.thread_id`; exact subtype trigger |
| Many-to-many | `users` | `threads` | `user_threads.user_id → users.user_id`; `user_threads.thread_id → threads.thread_id` |
| One-to-many | `threads` | `posts` | `posts.thread_id → threads.thread_id` |
| One-to-many | `posts` | `comments` | `comments.post_id → posts.post_id` |
| One-to-many, recursive | `comments` | `comments` | `(p_comment_id, post_id) → (comment_id, post_id)` |
| One-to-many, parent edge | `threads` | `threads_group` | `threads_group.p_thread_id → threads.thread_id` |
| One-to-many, child edge | `threads` | `threads_group` | `threads_group.c_thread_id → threads.thread_id` |
| Many-to-many | `threads` | `tags` | `threads_tag.thread_id → threads.thread_id`; `threads_tag.tag_id → tags.tag_id` |
| Many-to-many | `posts` | `tags` | `post_tag.post_id → posts.post_id`; `post_tag.tag_id → tags.tag_id` |

## Join and reference tables

- Lookup/reference tables: `roles`, `tags`.
- Many-to-many join tables: `user_roles`, `user_threads`, `threads_tag`, `post_tag`.
- `threads_group` is a self-referential hierarchy edge table, constrained to at most one parent per child.
- `project`, `course`, and `lab` are subtype tables sharing the `threads.thread_id` primary key.

## Python enums and database checks

Define Python enums and persist values as strings with database `CHECK` constraints:

- `RoleName`: `student`, `faculty`, `admin`
- `ThreadType`: `lab`, `course`, `project`
- `ThreadRestrictionLevel`: `open`, `restricted`, `closed`
- `PostType`: `announcement`, `discussion`
- `PostRestrictionLevel`: `inherited`, `open`, `restricted`, `closed`
- `CommentRestrictionLevel`: `inherited`, `open`, `restricted`, `closed`
- `ModerationStatus`: `active`, `reported`, `hidden_by_moderator`

## Index recommendations

- All FK columns, especially the association table FKs.
- `posts(thread_id, created_at)` for chronological thread timelines; `posts(user_id)` and `posts(post_type, mod_status)` for filters.
- `comments(post_id, created_at)` and `comments(p_comment_id)` for post retrieval and nested replies.
- `threads(user_id)` and `threads(thread_type, restriction_level)` for thread filters.
- `threads_group(p_thread_id)` for child lookup; `c_thread_id` is unique and indexed.
- Reverse tag lookup indexes: `threads_tag(tag_id, thread_id)` and `post_tag(tag_id, post_id)`.
- Consider a PostgreSQL GIN full-text index over post title/content and optionally comment content to support keyword searches.

## Lifecycle and enforcement

- Soft-deleting a user sets `users.deleted_at`; it does not delete associated rows. Set `restriction_level = 'closed'` on threads, posts, and comments created by that user.
- Directly deleting a thread or post deletes dependent data. Use cascading foreign keys for subtype rows, hierarchy edges, associations/tags, posts, comments, and nested comment replies. Deleting a parent thread must also delete descendant thread rows recursively; use a database trigger or equivalent transactional deletion operation for this behavior.
- Ensure every user has a role. When none is supplied at user creation, assign the seeded `student` role. Role removal must likewise avoid leaving a user with no roles.
- Enforce subtype completeness/type matching with deferred database constraint triggers; enforce thread hierarchy type rules with database triggers.
- Enforce that a parent comment belongs to the same post using the composite FK described above.

## Clarifications captured

- Thread names and descriptions intentionally remain in the three subtype tables.
- Moderation remains a simplified current-status field; no moderation-history table is planned.
- Comment restrictions now have their own field to support closing comments authored by a soft-deleted user. The default `inherited` value means normal comments continue to use their parent post's restriction behavior.
